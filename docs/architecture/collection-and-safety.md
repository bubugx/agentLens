# 采集、历史和清理策略

本文件为实现前决策；与接口契约一起评审。实际时效、开销和行为由后续实现、测试与代码审查验证，以下周期是设计预算。

## 1. RAM 和进程采样

| 数据 | 采样方式 | 初定周期/新鲜度 |
| --- | --- | --- |
| 系统内存 | ProcessInfo.physicalMemory + host_statistics64 + page size；pressure 单独读取系统值 | 2 秒；超过 4 秒未成功更新标过期 |
| 进程列表与 RSS | proc_listallpids、proc_pidpath、PROC_PIDTBSDINFO、PROC_PIDTASKINFO | 2 秒；超过 4 秒标过期；全局循环不重叠 |
| UI 快照 | 按变更合并到 AppStore | 最多每秒 1 次；系统/进程端到端目标 ≤5 秒 |
| RAM/RSS 历史 | 按 Agent 聚合和系统指标存储，保留成员与缺失数 | 30 秒一个点，保留 7 天；当前 2 秒采样不受历史分辨率限制 |

系统原始分量展示为 free/active/inactive/wired/compressor 物理页字节。若界面需要单一“已用估算”，采用 `total - min(total, free + inactive)`，标注“估算”并记录公式，不声称与活动监视器精确一致。先做乘法和求和溢出检查；未知值不参与完整结果。`compressedPhysicalBytes` 使用 compressor_page_count × pageSize，不把未压缩页数再算一次。各 VM 分量不作为互斥饼图，除非实现和测试已证明总和口径。内存压力使用 `kern.memorystatus_vm_pressure_level` 已知 1/2/4 映射 normal/warning/critical，其他值为 unknown；读取失败不从百分比伪造压力。

进程身份为 PID + 启动秒/微秒 + 路径 + UID。先枚举，再读身份/RSS，并在需要时复核实例未变；采样中退出与权限拒绝分别报告。进程聚合按身份去重，共享内存仍可能在不同进程 RSS 重复，显示“可读进程 RSS 合计”。进程存在只能证明“运行中”；文件变化和 CPU 增量作为独立活跃证据，不宣称因果。

进程规则首版仅识别明确的 `codex`、`claude` 可执行文件路径/名字组合，不读取命令行以避免采集提示词/密钥。名称命中是规则识别，不是代码签名真实性证明；证据包含匹配路径和规则。由解释器运行且不能据 executablePath 判别的 CLI 保持未知，不泛化 `node/python` 为 Agent。若增加 verifiedParentChain，必须验证同 UID、父子启动身份且有链长上限，不能把所有编辑器子进程都算作 Agent。规则和未知案例由 technical-core 评审确认并写入实现文档。

## 2. 目录发现与归属

本机仅做了路径存在性探测，未读取这些目录内的文件内容。实际结果见 evidence/discovery.json。

| 规则 | 自动发现入口 | 本机事实 | 分类/安全默认 |
| --- | --- | --- | --- |
| `codex-home-v1` | `~/.codex` | 根、sessions、archived_sessions、tmp 存在；log 不存在 | sessions/archived_sessions 为受保护会话数据；tmp 可分类临时数据，但不直接等于可删除 |
| `claude-home-v1` | `~/.claude` | 根存在；projects/debug/cache/tmp 在探测时不存在 | 存在时才展示子类；其余内容未知/设置，默认保留 |
| 自定义根 | NSOpenPanel 选择的用户目录 | 由后续用户选择，不扩大为全盘扫描 | 默认 unknown；用户可标记关联 Agent，正常产出与未知项默认保留 |

Cursor 和 Lumo 目录在本机存在，但首版自动发现只承诺上表两个可解释入口。其余可作为自定义监测目录；在进一步核实格式前，不把应用整体占用叫作 Agent 产出。对于 `CODEX_HOME` 等自定义安装位置，不猜测另一个进程的环境；通过用户添加目录支持，后续经评审可扩展显式配置。

归属证据优先级：已知目录规则/进程可执行身份分别用于各自范围；用户标签只表示用户关联；文件变化时间与进程同时存在是弱相关，不能覆盖未知写入者。目录统计可标“Codex 存储目录”，但不能标“这些历史文件均由本次 Codex 生成”。第一代完整扫描建立 baseline，新增量从 baseline 后的可比完整代次计算。

类别采用 output、sessionData、cache、logs、temporary、settings、unknown。命名包含 cache/tmp/log 只是弱线索；只有**命中确切且已评审的根内相对目录规则**才能产生可清理候选。会话、数据库、凭据/配置、源代码和正常产出默认保留。不读取文件内容，不解析认证文件。清理规则可能为空，这时展示“当前无符合安全规则的候选”，不可制造垃圾文件数量。

## 3. 扫描、增量和性能边界

1. 根注册时核验真实目录、卷/文件身份、权限与监测边界。拒绝符号链接根，或要求用户显式选择实际目标；拒绝重叠根/同一身份别名，防止重复统计和重复清理。枚举默认不跟随符号链接，不跨卷挂载边界；跳过的范围必须出现在 coverageNotes，不能当作完整零值。
2. 先订阅 FSEvents 再开始基线扫描；扫描中事件积入合并集合，结束后补扫变动子树。首次基线以一个已提交的可比代次为界，不从扫描前的历史条目推导新增。扫描不是原子文件系统快照，记录 sampleStart/sampleEnd；持续变化无法收敛时显示不完整/仍在协调。
3. FSEvents 仅作为“目录需要重新读取”的提示，不是文件写入者证据，也不是完整审计日志。debounce 1 秒，连续变化最长 3 秒即调度一次；不让不停写入导致永远不刷新。目标是稳定变化后 10 秒内形成完整结果；实际由性能任务测量。
4. 全扫描串行、utility 优先级；元数据批次初定 512 条，批次间检查取消。索引落 SQLite，避免在内存里维护整个树。文件明细/排行查询分页，UI 不加载数万行；没有全量文件内容读取或每秒运行 du/lsof/ps 子进程。
5. 事件按根和最小脏子树合并，单根最多 1024 个待处理子树；溢出升级为一次全根 reconcile。扫描未完成时不并发启动同根扫描。扫描结果必须核对 root identity 和配置 revision，避免暂停/移除后写回过时结果。
6. FSEvents dropped、mustScanSubDirs、rootChanged、睡眠恢复等触发全根 reconcile。根消失保留历史并停止跟随；同路径新建不同 inode 不自动当作原根，需提示重新确认。每 60 秒做健康复核；事件订阅失败可用 5 秒轮询降级，但必须显示降级状态并重测时效/CPU，未达标需修复或明确未通过。
7. 只有完整成功代次才能推断删除和净变化；权限失败/扫描取消时不将未访问条目标记删除。部分观测只显示已观测量或最后完整值并注明状态。恢复权限后重新完整扫描再比较。
8. 用卷 ID + 文件 ID 辅助识别重命名，路径仍是条目身份的一部分以正确处理硬链接。同身份改名不增加/减少文件数；已存在文件增大计入 modifiedDeltaBytes。身份不可用时明示为路径条目差异，不能声称精确重命名识别。

持续增长提示先使用明确规则：最近 5 个完整的 60 秒桶均有净增长，且总增量 ≥10 MiB 时显示“连续 5 分钟增长”；不足窗口不判定。提示展示窗口、规则和增量，不叫作内存泄漏。系统 RAM、RSS 和磁盘增长分别分析，不共用一个“增长”指标。创建后在两次扫描之间又删除的文件可能未被观测到，必须说明这是采样监测而非完整文件操作审计。

## 4. 历史存储与恢复

采用系统 SQLite，经 CSQLite module map 和 `#include <sqlite3.h>` 接入；无需 pkg-config 或外部下载。单 writer 使用 WAL + foreign_keys，busy timeout 有上限。关键清理 journal 使用可靠提交策略（如同步 FULL）；性能优化不可牺牲操作结果持久性。

存储默认位于 `~/Library/Application Support/AgentLens/`，不进入监测范围；目录权限仅当前用户，数据库文件限制为当前用户可读写。此位置是后续应用运行写入的约定，本阶段未在该目录创建数据库。存储路径、文件名、进程路径属于本地私密元数据，默认不上传、不记录命令行或内容，诊断日志避免完整用户路径。

建议最小表：schema_version、roots、scan_generations、file_index、growth_points、resource_points、cleanup_operations、cleanup_items。持久化 root 的首次 baseline 与 epochID；完整代次事务提交索引差异和摘要，崩溃时不暴露半个代次。大扫描可用 staging generation 分批落盘，完成后原子切换；过时 staging 下次启动清理，不将其展示为完成。

- 目录当前索引持久化；基线不每次启动重置。重启先显示“历史数据，等待复核”，再核验身份、完整扫描和比较。应用未运行期间的净差量标“离线区间差异”，不知道准确发生时间，不逐点补造。
- 目录趋势按 10 秒窗口合并发生的变化并至少每 60 秒记录健康样本，近 24 小时保留该分辨率；24 小时～7 天按分钟聚合。RAM/RSS 每 30 秒记录一次，保留 7 天；磁盘按完整代次提交，不能等历史合并后才保存基线。
- RAM/RSS 实时采样保留最近 60 点在内存中；图表最多 500 点/页。清理记录保留 30 天，根配置/当前索引不按 7 天自动删除；日志滚动并有大小上限。移除根可选保留历史，不删除磁盘文件。
- 正常退出刷新已完成写入；非关键 RAM 历史最坏丢失最后一个 30 秒桶，但当前完整文件代次和清理结果需要事务持久化。磁盘满/权限错误显示 persistenceState，实时只读监测可继续，但阻断新清理，避免无记录地移动文件。
- 打开库失败、损坏或未知 schema 时保留原文件并显示原因，不静默覆盖；若能隔离坏库，明确提示新历史起点再建新库。未来版本 schema 只读/停止写入，不做破坏性降级。迁移必须事务执行且先备份，不假设日志等于数据库恢复。

## 5. 清理复核与故障边界

首版仅移动经过明确规则命中的**普通文件**，不递归清理目录，不清理符号链接、硬链接、设备/套接字、挂载点、根目录、未知/输出/配置/会话数据库。已知临时文件最低静置 24 小时，已知日志最低 7 天；只是保守阈值，不是“文件无用”的证明，理由必须展示。

候选需在间隔至少 10 秒的两次元数据观测中稳定，最近 60 秒无相关文件事件；所属 Agent 仍运行、进程可读性不足或活动性无法确认时保守跳过对应候选。可见的写入打开状态可作为额外否决证据；两次 mtime 稳定不能证明没有写入者，不把它称作“已确认未被占用”。自定义未知根默认只监测、不自动生成清理候选；可在后续明确配置并评审缓存子目录规则。

执行契约：

1. UI 请求 prepare；Core 读取可信候选，验证相对路径无 `..`/绝对覆盖，按路径组件和 root 身份验证范围，检查每级祖先与末端均非符号链接。使用 no-follow 元数据，不能只做字符串前缀或 resolve 后比较。
2. 记录 fingerprint：卷/文件 ID、类型、大小、mtime/ctime 的纳秒值、linkCount、根与祖先身份。排除父子候选和重复文件 ID。读失败、身份改变、权限不明、仍有近期活动均返回不可执行理由。
3. 计划 60 秒有效，显示路径、逐项逻辑大小、类别、规则、关联证据、排除项和“移入废纸篓，可在 Finder 恢复；不会立即释放磁盘空间”。用户明确确认 planID/digest 后才执行。
4. 每项执行前重新 no-follow 验证 fingerprint、根/祖先身份、规则、授权和静置条件。变化则 skipped(changedSinceConfirmation)，消失则 alreadyGone；不把已消失大小算入 movedLogicalBytes。禁止静默替换为新文件执行。
5. 先将 operation/item intent 持久化，再调用 `FileManager.trashItem(at:resultingItemURL:)`，成功后保存返回的废纸篓 URL、时间和结果；若不能移入废纸篓，返回 failed，**不得回退到 removeItem/unlink**。单项失败继续反馈其他项；一批串行，便于避免同路径并发和恢复歧义。
6. 成功移动后主动 dirty/reconcile 根，让统计与趋势反映真实变化，不能只从卡片减去估算大小。卷可用空间按卷分组采样动作前/后并标时间与 availability；它可能受其他进程/APFS 快照影响，可能为 0 或负，不能归功为“已释放”。
7. 崩溃重启对未完成 intent 检查原身份和已记录 trash 目标；不重放移动，不将“原路径不存在”直接算成功。无法确认则 unknownAfterInterruption，显示需要人工检查，保留恢复信息。已移入废纸篓但结果落库失败要明确提示，不能重复操作。

**已知残余风险：** `trashItem` 是按路径调用，元数据复核和系统移动之间没有通用的原子“比较 inode 后移入废纸篓”API。no-follow 和祖先身份检查能发现常见替换，但不能在有同 UID 进程恶意/高速换路径时证明完全消除 TOCTOU；NSFileCoordinator 也只协调合作进程。首版以保守候选、近期活动否决、单项即时复核和不递归清理缩小风险。technical-core 与 code-review 必须专门审查竞态夹具；若现有实现无法保证不跟随替换的祖先，应禁用该项清理并报告阻塞，不能为赶进度移除复核。需要对抗性路径安全保证时，另行评审基于受控 staging/文件描述符的原子重命名和恢复 journal，不能将它当作本版已完成能力。

恢复说明以 Finder 废纸篓“放回”为主，必要时提供打开废纸篓/查看原路径。跨卷、网络卷、不支持废纸篓、用户已清空废纸篓等情况必须明确，不承诺永久可恢复；应用不实现未经评审的自动恢复覆盖原文件。
